# Conventional Commits Reference

**Purpose**: Commit message format standards for source-control skill

**Specification**: https://www.conventionalcommits.org/

---

## Template

```
<type>(<scope>): <subject>

<body>

<footer>
```

---

## Types

| Type | Description | Example |
|------|-------------|---------|
| `feat` | New feature | `feat(auth): add OAuth2 login` |
| `fix` | Bug fix | `fix(api): handle null response` |
| `refactor` | Code restructuring (no behavior change) | `refactor(core): extract helper` |
| `docs` | Documentation only | `docs(readme): update install steps` |
| `test` | Adding or updating tests | `test(auth): add JWT validation` |
| `build` | Build system or dependencies | `build(deps): update pydantic` |
| `style` | Code style/formatting | `style: apply ruff formatting` |
| `chore` | Maintenance tasks | `chore: update gitignore` |
| `ci` | CI/CD pipeline changes | `ci: add Python 3.13 matrix` |
| `perf` | Performance improvements | `perf(query): add index` |
| `revert` | Revert previous commit | `revert: feat(auth) OAuth2` |
| `wip` | Work in progress | `wip: partial refactor` |


---

## Scope Guidelines

**Format**: Lowercase, hyphenated if multi-word

**Examples by Domain**:

| Domain | Scope Examples |
|--------|----------------|
| Agents | `agent-source-control`, `agent-debugger` |
| Packages | `core`, `api`, `auth` |
| Documentation | `docs`, `readme`, `changelog` |
| Infrastructure | `ci`, `docker`, `k8s` |
| Project | `project`, `config` |

---

## Subject Line Rules

1. **Imperative mood**: "add feature" not "added feature"
2. **No capitalization**: Start lowercase
3. **No period**: Don't end with `.`
4. **Max 50 chars**: Brief and scannable
5. **Complete the sentence**: "This commit will..."

**Good**: `feat(auth): add password reset flow`
**Bad**: `feat(auth): Added password reset flow.`

---

## Body Guidelines

- Wrap at 72 characters
- Explain WHAT and WHY, not HOW
- Use bullet points for multiple changes
- Separate from subject with blank line


```
feat(agent-source-control): redesign as three-operation worker

- analyze_changes: intelligent file grouping with 6 heuristics
- execute_commits: selective commit execution with error recovery
- monitor_ci: GitHub Actions monitoring with UV awareness

Removes architectural violations (sub-agent delegation).
```

## Breaking Changes

Use `!` after type/scope for breaking changes:

```
feat(api)!: change response format

BREAKING CHANGE: Response now returns array instead of object.
```

## Multi-line Commit via Heredoc

For programmatic commits, use heredoc to stdin:


```bash
AGENT_NAME=source-control git commit -F- <<'EOF'
feat(agent-source-control): add three-operation git agent

- analyze_changes: intelligent file grouping
- execute_commits: selective commit execution
- monitor_ci: GitHub Actions monitoring

Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
```

**Why heredoc**:
- Pipes message directly (no temp files)
- Handles multiline safely (quoted `<<'EOF'`)
- No shell parsing of message content
- Standard git practice for programmatic commits
