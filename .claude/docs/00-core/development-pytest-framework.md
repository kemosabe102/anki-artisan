## Overview

pytest execution framework provides structured mechanisms for running tests, interpreting results, and categorizing failures. Understanding pytest exit codes, output formats, and structured parsing enables automated test execution agents to make intelligent decisions about retries, delegations, and failure categorization.

**Key Concepts**:

- **Exit Codes**: Standardized return codes (0-5) indicating test execution outcomes

- **Structured Output**: Machine-parseable formats (JSON, XML) for detailed result analysis

- **Result Interpretation**: Mapping pytest output to actionable agent decisions

## Core Frameworks

### Framework 1: pytest Exit Code Interpretation

**Purpose**: Translate pytest exit codes into actionable decisions for test execution agents

**When to Use**:

- After any pytest execution to determine success/failure

- When deciding whether to retry vs halt execution

- When categorizing failures for delegation

**Components**:

1. **Exit Code 0 (Success)**: All tests passed, no failures

2. **Exit Code 1 (Test Failures)**: One or more test assertions failed

3. **Exit Code 2 (Interrupted)**: User interrupted execution (Ctrl+C)

4. **Exit Code 3 (Internal Error)**: pytest internal error

5. **Exit Code 4 (Usage Error)**: Command-line usage error

6. **Exit Code 5 (No Tests Collected)**: No tests found matching criteria

**How to Apply**:

1. Execute pytest and capture exit code: `result = subprocess.run(['pytest', ...], capture_output=True)`

2. Check `result.returncode` against exit code meanings

3. Map to agent action:
   - `0` → Report success, no further action

   - `1` → Parse failures, categorize, delegate fixes

   - `2` → Report interruption, ask user to retry

   - `3` → Escalate to orchestrator (pytest bug or environment issue)

   - `4` → Fix command-line arguments, retry

   - `5` → Verify test discovery patterns, check file paths

**Example from Codebase**:

```python
    """Map pytest exit code to semantic result."""































































































































    match exit_code:































































































































        case 0:































































































































            return "success"































































































































        case 1:































































































































            return "test_failure"































































































































        case 2:































































































































            return "interrupted"































































































































        case 3:































































































































            return "internal_error"































































































































        case 4:































































































































            return "usage_error"































































































































        case 5:
```

### Framework 2: Structured Output Selection

**Purpose**: Choose the appropriate pytest output format for machine parsing based on agent needs

**When to Use**:

- When executing tests and need to parse results programmatically

- When detailed per-stage information (setup/call/teardown) is required

- When integrating with CI/CD systems

**Components**:

1. **JSON Format (pytest-json-report plugin)**: Rich structured data with per-stage results, full error context, test metadata

2. **JUnit XML**: Standard format for CI/CD integration, test suite/case hierarchy

3. **Plain Text**: Human-readable but requires regex parsing

**How to Apply**:

1. For agent-driven analysis → Use JSON format:

   ```bash































































































































   uv run pytest --json-report --json-report-file=results.json































































































































   ```

2. For CI/CD integration → Use JUnit XML:

   ```bash































































































































   uv run pytest --junit-xml=results.xml































































































































   ```

3. Parse structured output:

   ```python































































































































   import json































































































































   with open("results.json") as f:































































































































       results = json.load(f)































































































































       failures = results["tests"]































































































































       for test in failures:































































































































           if test["outcome"] == "failed":































































































































               # Access per-stage details































































































































               setup_error = test.get("setup", {}).get("longrepr")































































































































               call_error = test.get("call", {}).get("longrepr")































































































































   ```

```python
    failures = {































































































































        "setup_failures": [],































































































































        "call_failures": [],































































































































        "teardown_failures": []































































































































    }































































































































































































































































    for test in data.get("tests", []):































































































































        if test["outcome"] == "failed":

                failures["setup_failures"].append(test)































































































































            elif "call" in test and test["call"].get("outcome") == "failed":































































































































                failures["call_failures"].append(test)































































































































            elif "teardown" in test and test["teardown"].get("outcome") == "failed":































































































































                failures["teardown_failures"].append(test)































































































































































































































































    return failures































































































































```

**Trigger Conditions**:

- Agent receives test execution request

- Need to determine pass/fail and next actions

**Steps**:

   - **Input**: Test path, pytest arguments

   - **Output**: Exit code, stdout/stderr

   - **Rationale**: Capture all execution information for analysis


2. **Interpret Exit Code**
   - **Input**: result.returncode

   - **Output**: Semantic result (success, test_failure, etc.)

   - **Rationale**: Map numeric code to actionable decision

   ```python































































































































   outcome = interpret_pytest_exit_code(result.returncode)































































































































   ```

3. **Parse Structured Output (if exit code 1)**
   - **Input**: results.json path

   - **Output**: Parsed failure details

   - **Rationale**: Extract detailed failure information for categorization

   ```python

   ```

4. **Make Decision**
   - **Input**: Exit code interpretation, parsed failures

   - **Output**: Next action (retry, delegate, escalate, report success)

   - **Rationale**: Route to appropriate handler based on failure type

**Success Criteria**:

- ✅ Exit code correctly mapped to semantic outcome

- ✅ Structured output parsed without errors

- ✅ Appropriate next action determined

**Failure Handling**:

- If exit code 3 (internal error), escalate to orchestrator with pytest logs

- If exit code 4 (usage error), fix command-line args and retry once

- If exit code 5 (no tests), verify test paths and report to user

## Best Practices

### Practice 1: Always Capture Exit Codes

**Principle**: Exit codes are the primary signal for test execution outcomes

**Implementation**:

- Use `subprocess.run()` instead of `subprocess.call()` to capture exit code

- Store exit code in execution metadata for debugging

- Never ignore exit codes - always interpret them

**Benefits**:

- ✅ Reliable success/failure detection

- ✅ Enables intelligent retry logic

- ✅ Provides context for delegation decisions

**Trade-offs**:

- ⚠️ Requires exit code interpretation logic

- ⚠️ Exit code alone insufficient for detailed failure analysis

**Example**:

```python































































































































# ✅ Correct: Capture and interpret exit code































































































































result = subprocess.run(["pytest", path], capture_output=True)































































































































exit_code = result.returncode































































































































outcome = interpret_pytest_exit_code(exit_code)































































































































































































































































# ❌ Wrong: Ignore exit code































































































































subprocess.run(["pytest", path])  # No exit code capture































































































































```

---

### Practice 2: Prefer JSON Format for Agent Parsing

**Principle**: Structured JSON output is easier and more reliable to parse than plain text

**Implementation**:

- Install pytest-json-report plugin: `uv add pytest-json-report`

- Always use `--json-report --json-report-file=path` for agent executions

- Parse JSON with standard library (no regex needed)

**Benefits**:

- ✅ No regex parsing fragility

- ✅ Access to per-stage results (setup/call/teardown)

- ✅ Rich error context and metadata

**Trade-offs**:

- ⚠️ Requires plugin installation

- ⚠️ Larger output files than plain text

- ⚠️ May need fallback to XML if plugin unavailable

**Example**:

```python































































































































# ✅ Preferred: JSON parsing































































































































import json































































































































with open("results.json") as f:































































































































    data = json.load(f)































































































































    failures = [t for t in data["tests"] if t["outcome"] == "failed"]































































































































































































































































# ❌ Anti-Pattern: Regex parsing of plain text































































































































import re































































































































output = subprocess.run(["pytest"], capture_output=True, text=True).stdout































































































































failures = re.findall(r"FAILED (.*?) - (.*)", output)  # Fragile!































































































































```

## Anti-Patterns

### Anti-Pattern 1: Ignoring Exit Code 5 (No Tests Collected)

**Problem**: Treating "no tests collected" as success when it may indicate configuration issues

**Detection**:

- 🔴 Exit code 5 returned but agent reports success

- 🔴 Test discovery patterns not validated

- 🔴 Silent failures when test paths are wrong

**Consequences**:

- ❌ False sense of test coverage

- ❌ Missing test execution goes unnoticed

- ❌ Broken CI/CD pipelines

**Better Approach**:

```python































































































































✅ Preferred Pattern:































































































































if exit_code == 5:































































































































    # Investigate why no tests collected































































































































    verify_test_paths()































































































































    check_test_discovery_patterns()































































































































    report_warning_to_user("No tests found matching criteria")































































































































































































































































❌ Anti-Pattern:































































































































if exit_code == 0 or exit_code == 5:































































































































    return "success"  # Treating no tests as success!































































































































```

**Migration Strategy**:

1. Audit existing test execution code for exit code 5 handling

2. Add verification logic for test discovery when exit code 5

3. Report warnings to users when no tests collected

### Anti-Pattern 2: Using Plain Text Parsing When JSON Available

**Problem**: Regex parsing of plain text output is fragile and error-prone

**Detection**:

- 🔴 Regex patterns used to extract test failures from stdout

- 🔴 Hardcoded line number expectations

- 🔴 Parsing failures when pytest output format changes

**Consequences**:

- ❌ Brittle parsing logic that breaks with pytest updates

- ❌ Missed failures due to regex mismatches

- ❌ Inability to access per-stage details

**Better Approach**:

```python































































































































✅ Preferred Pattern:































































































































# Use JSON format with structured parsing
```

1. Install pytest-json-report plugin: `uv add pytest-json-report`

2. Update test execution code to use `--json-report`

3. Replace regex parsing with JSON parsing

4. Add fallback to JUnit XML if JSON plugin unavailable

## Integration Points

### Integration 1: Orchestrator Coordination

**Purpose**: Define how the orchestrator (Claude Code) coordinates with code-quality for test execution and failure delegation

**Relationship**:

- code-quality provides pytest execution and failure categorization

- Orchestrator coordinates agent delegation based on code-quality recommendations

**Coordination Pattern**:

1. **Orchestrator Delegates to code-quality**
   - User requests test execution (e.g., "run tests", "validate changes")

   - Orchestrator uses Task tool with subagent_type="code-quality"

   - Provides test scope (file paths, test names, or full suite)

2. **code-quality Executes and Categorizes**
   - Runs pytest with configured options

   - Captures failures and categorizes each (APPLICATION_BUG, TEST_BUG, ENVIRONMENT, FLAKY)

   - Returns structured results with delegation recommendations

3. **Orchestrator Receives Recommendations**
   - Parses code-quality output including failure categories

   - Reviews delegation suggestions (debugger for APPLICATION_BUG, code-quality for TEST_BUG)

   - Spawns appropriate specialist agents based on confidence scores

4. **Agent Coordination Loop**
   - Specialist agents (debugger, code-quality) fix issues

   - Orchestrator calls code-quality again to verify fixes

   - Repeats until tests pass or max iterations reached (3)

   - Escalates to user if confidence drops below threshold (<0.5)

**Example Delegation**:

Orchestrator delegates test execution via Task tool, receives categorized failures, then spawns debugger for APPLICATION_BUG or code-quality for TEST_BUG based on confidence scores.

**Key Benefits**:

- Clear separation: orchestrator coordinates, code-quality executes

- Intelligent routing: failures automatically directed to right specialist

- Loop protection: max 3 iterations prevents infinite retry cycles

- Confidence-based escalation: low confidence triggers human review

## Validation & Quality Checks

### Check 1: Exit Code Interpretation Correctness

**What to Validate**: Exit code mapping to semantic outcomes is accurate

**Validation Method**:

1. Create test cases for each exit code (0-5)

2. Execute pytest with conditions that trigger each exit code

3. Verify semantic outcome matches expected result

**Pass Criteria**: All exit codes correctly mapped to semantic outcomes

**Fail Criteria**: Any exit code misinterpreted or missing

**Remediation**: Update `interpret_pytest_exit_code()` function with correct mapping

---

### Check 2: JSON Parsing Robustness

**What to Validate**: JSON parsing handles all pytest-json-report schemas correctly

**Validation Method**:

1. Generate pytest JSON reports with different failure types (setup, call, teardown)

2. Parse each report and extract failures

3. Verify all failure details extracted correctly

**Pass Criteria**: All failure types parsed with complete information

**Fail Criteria**: Missing failures, incomplete details, parsing errors

**Remediation**: Update JSON parsing logic to handle missing keys, schema variations

## Common Pitfalls & Solutions

| Pitfall | Detection | Solution |

|---------|-----------|----------|

| Exit code 5 treated as success | Check for `exit_code == 5` → success mapping | Add explicit handling for "no tests collected" case |

| JSON plugin not installed | ImportError or missing --json-report option | Install pytest-json-report or fallback to JUnit XML |

| Plain text parsing breaks on output changes | Regex match failures, incomplete failure lists | Switch to JSON format with structured parsing |

| Ignoring per-stage failure details | Only using exit code, missing setup/teardown failures | Parse JSON report for stage-level failure information |

| Hardcoded output file paths | File conflicts in parallel execution | Generate unique output paths with timestamps or UUIDs |

## Glossary

- **Exit Code**: Numeric return value from pytest indicating execution outcome (0-5)

- **Structured Output**: Machine-parseable formats (JSON, XML) containing detailed test results

- **Per-Stage Results**: Failure information broken down by setup, call, and teardown phases

- **Semantic Outcome**: Human-readable interpretation of exit code (e.g., "test_failure", "success")
