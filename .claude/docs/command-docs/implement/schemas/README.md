# Implement Command Schemas

Schema documentation for the `/implement` command.

## Files

| File | Purpose |
|------|---------|
| `implement.schema.json` | TASKS.json schema reference (input: what orchestrator parses) |
| `implementation-state.schema.json` | IMPLEMENTATION_STATE.json schema (output: execution state for resume) |

## Schema Overview

The `/implement` command parses TASKS.json files generated by `/tasks`. This schema defines the expected structure.

## Key Schema Elements

### Meta Section
- `component_name`: Plan identifier (e.g., "001-infrastructure-foundation")
- `feature_name`: Parent feature name
- `plan_file`: Path to PLAN.md
- `spec_file`: Path to SPEC.md

### Tasks Array
- `task_id`: Unique identifier (e.g., "T001")
- `agent`: Agent to delegate to
- `description`: Task description
- `file_path`: Target file
- `phase`: Grouping phase
- `review_group`: Associated review group
- `parallel`: Can run in parallel
- `dependencies`: List of dependent task IDs

### Review Groups
- `group_id`: Unique identifier (e.g., "RG001")
- `task_range`: Tasks covered (e.g., "T001-T006")
- `review_task`: Task ID for review checkpoint
- `files_in_scope`: Files to review
- `max_iterations`: Retry limit (typically 3)

### Dependency Graph
- Phase-to-task mappings
- Blocking relationships

## Validation

The orchestrator validates:
1. Schema compliance
2. Task ID uniqueness
3. Dependency validity
4. Review group completeness

## IMPLEMENTATION_STATE.json Schema

Machine-parseable execution state for reliable mid-execution resume.

### Key Sections

| Section | Purpose |
|---------|---------|
| `meta` | Execution metadata (phase, status, timestamps, resume_count) |
| `tasks` | Per-task state map (status, checksums, error_details) |
| `review_groups` | Per-review-group state (iteration, fix_history, unresolved_issues) |
| `blocked_cascade` | Dependency blocking graph (root_blockers, cascade_map) |
| `file_checksums` | Current checksums for conflict detection on resume |
| `statistics` | Aggregated metrics for completion report |

### Dual-File Architecture

The `/implement` command uses two complementary files:

1. **IMPLEMENTATION_STATE.json** - Machine-parseable (this schema)
   - Written after EVERY task completion
   - Used by `--resume` to reconstruct execution state
   - Contains checksums for conflict detection

2. **IMPLEMENTATION_PROGRESS.md** - Human-readable
   - Updated at review checkpoints only
   - Provides developer visibility into progress
   - Not used for resume logic

See `workflow-phases.md` section "State Persistence Architecture" for complete details.
